# 2026.309.0459 — feat(image): add the k3s control-plane lease image pod-crabbox-k3s

## Summary

Adds `pod-crabbox-k3s`: the k3s control-plane lease image for the Crabbox `containerd` provider, one of the `pod-crabbox-<variant>` images tracked by opencharly/opencharly#869 (W5.2). It is the pinned `opencharly/pod-crabbox-nested` lease contract plus the pinned k3s multi-call binary, its runtime dependencies, the `node-ip`/rootless drop-in, the `k3s0` dummy link, the process-only k3s unit, and a readiness hook that checks a Ready node **and** a workload exec.

- **`charly.yml`** — the image: `base: ghcr.io/opencharly/pod-crabbox-nested:2026.309.0149` (pinned OCI base), `user: root` with `entrypoint: [/sbin/init]` (the inherited systemd-as-PID-1 handoff), and `distro: [cachyos, arch]` + `build: [pac]` declared explicitly because an external OCI base does not inherit the CachyOS chain. The nested repo's own `charly.yml` carries `import: []`, so it exposes no namespace to qualify: the base is the published OCI artifact, exactly as `pod-crabbox-nested` bases on `pod-crabbox-systemd`.

  - the runtime packages the row names (`sqlite`, `procps-ng`, `kmod`, `iputils`) plus the layer-k3s candy's (`conntrack-tools`, `socat`, `ethtool`, `fuse-overlayfs`, `ca-certificates`); `iptables-nft` is provided by the base image's `iptables` package and is asserted rather than re-declared;

### Scope notes

- **Where each requirement comes from.** The k3s version, the sha256-verified multi-call install and the runtime package list come from `opencharly/layer-k3s`'s `k3s` candy. The shared-containerd endpoint and the two CNI keys come from `K3S.md` §1–§2. The unit settings (`KillMode=process`, `Delegate=yes`, `Restart=always`, no `ExecStartPre=modprobe`), `node-ip: 172.31.255.1`, `k3s-dummy.service`, `write-kubeconfig-mode`, the TLS SAN and the `KubeletInUserNamespace` gate come from `CONTAINERD-IMAGES.md` §2's `pod-crabbox-k3s` row — neither layer-k3s nor K3S.md specifies them. The readiness-hook contract comes from `CONTAINERD-IMAGES.md` §2.1.
- **The checksum is verified by the gate, not by a build-time command step.** A `command:` run step is baked into the plan and skipped as mutating in `charly check box` (verify-only), which would put a `SKIP` line in the gate. The binary is installed with `download:` and the release's own manifest ships in the image, so a deterministic `check:` compares the two. A wrong or truncated download therefore fails the gate; it cannot pass.
- **k3s uses the inner containerd.** The nested image already runs `containerd.service` (nerdctl-full) with `bridge_ip = "10.99.0.1/24"`; k3s points at that socket instead of starting a second embedded daemon (K3S.md §1). The two CNI keys are the only k3s-specific addition that daemon needs.
- **`iptables-nft` is the base image's.** Arch's `iptables` package owns `/usr/bin/iptables-nft`; declaring the `iptables-nft` package would fight a package-owned file, so the image asserts the command instead.
- **Rootless needs the host's `dummy` module.** `k3s-dummy.service` runs `ip link add k3s0 type dummy` as namespace-root inside the lease. A rootless lease has `CAP_NET_ADMIN` in its own user namespace but cannot `modprobe`, so the host must already have `dummy` loaded. This is stated in `README.md`.
- **The readiness workload probe needs egress.** k3s's shared containerd ships no images, so the kubelet's pause image and any workload are pulled on demand; the probe's `alpine:3.21` is no exception. The hook reports the elapsed time and fails honestly when the lease has no egress. This is stated in `README.md`.
- **`--device /dev/kmsg` is a consumer run flag.** The row requires it; the image cannot pass its own device. `README.md` names it beside the `--systemd=always` handoff.
