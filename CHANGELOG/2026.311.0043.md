# 2026.311.0043 — feat(bed): add the k3s control-plane R10 bed

Adds the disposable R10 bed for the `pod-crabbox-k3s` control-plane image, and the four image/bed fixes the bed found. The bed now PASSES end to end.

## Summary

The bed `check-pod-crabbox-k3s-cluster` is `disposable: true` and drives the image in three steps: **ABSENCE** (k3s is not serving, no kubeconfig, the readiness hook cannot pass, the lease refuses a freshly generated key), **PERFORM** (the lease consumes its inputs, the image's own units start the inner engine, the node address and k3s), **PRESENCE** (the node is Ready, a workload schedules and execs through apiserver → kubelet in the inner containerd, and the lease still holds over SSH).

It failed for several rounds, and every failure was real. Three of the four fixes are in `charly.yml` and `candy/k3s-lease/`; the fourth was a host prerequisite, fixed persistently outside the repo.

### 1. `/proc/sys` is read-only in a rootless podman lease

kube-proxy died at start:

```
kube-proxy exited: unable to create proxier: unable to create ipv4 proxier:
can't set sysctl net/ipv4/conf/all/route_localnet to 1:
open /proc/sys/net/ipv4/conf/all/route_localnet: read-only file system
```

`/proc/sys` is mounted `ro` in a rootless lease and no capability changes that. The lease now runs `privileged: true`, which is what the real Crabbox provider does for `Nested == "on"` (`nerdctl --privileged --security-opt privileged-without-host-devices --device /dev/kmsg -v <stateVolume>:/var`).

`security_opt: privileged-without-host-devices` was tried and **dropped**: it is a nerdctl option and podman 6.1.4 rejects it as invalid.

### 2. The bed omitted the `/var` state volume the nested contract requires

`CONTAINERD-IMAGES.md` §2 gives `/var` as the state volume. Without it `/var/lib/containerd` sits on the outer overlayfs and the inner overlayfs snapshotter rejects its own upperdir:

```
fsconfig() failed: overlay: filesystem on
/var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/100/work
not supported as upperdir
```

k3s surfaced that as `failed to mount rootfs component: invalid argument`, and every pod sat in `ContainerCreating`. The bed now declares the `lease-state` volume at `/var`.

### 3. A rootless lease cannot lower `oom_score_adj`

kubelet asks for `-998`:

```
OCI runtime create failed: write to /proc/self/oom_score_adj: Permission denied
```

Fixed with containerd's documented clamp, not by relaxing anything:

```toml
[plugins.'io.containerd.cri.v1.runtime']
  restrict_oom_score_adj = true
```

in a new `/etc/containerd/conf.d/60-k3s-cri-oom.toml`, plus a build-scope `check:` (`k3s-cri-oom-score-adj`) that proves the drop-in is present in the image.

### 4. Two host prerequisites, fixed persistently

- `dummy` — `/etc/modules-load.d/charly-pod-crabbox-k3s.conf`
- `br_netfilter` — `/etc/modules-load.d/charly-k3s-br-netfilter.conf`

Without `br_netfilter`, `bridge-nf-call-iptables` does not exist and `k3s.service` sits in `activating` forever with `runtime core not ready`.
